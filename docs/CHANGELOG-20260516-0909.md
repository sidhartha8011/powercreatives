# Changelog - 2026-05-16 09:09

## Brand Asset Role Contract + Logo Flow Fix

Senior-Dev solution to establish an explicit `role` contract between asset producers (upload mutations) and consumers (image generation, copy, video). Replaces the implicit `assets[0] = logo` convention with explicit `role='logo'`, backed by an idempotent data migration. No silent fallbacks anywhere in the chain.

### Backend
- **`power-creatives.php`** — bumped `PCM_DB_VERSION` from `1.3.0` to `1.4.0`.
- **`includes/class-pcm-activator.php`** — `maybe_upgrade()` calls new migration when installed version < 1.4.0.
- **`includes/core/db/class-pcm-schema.php`** — added `migrate_brand_assets_role()`: scans every brand row, parses `assets` JSON, sets `role='logo'` on `assets[0]` and `role='reference'` on the rest for assets missing the field. Idempotent — assets that already have a role are untouched, brands with no changes are not re-written.
- **`includes/modules/brands/service.php`** — `upload_asset()`, `add_asset_from_url()` and `create_asset_entry()` now require `role` (was optional). Added `assert_valid_role()` with `ALLOWED_ASSET_ROLES = ['logo', 'certification', 'reference']` constant. Throws `InvalidArgumentException` on missing/unknown role.
- **`includes/modules/brands/controller.php`** — REST endpoints catch `InvalidArgumentException` and convert to `400 Bad Request` with `pcm_invalid_role` code.

### Frontend
- **`app/shared/brandAssetResolver.ts`** (NEW) — canonical resolvers: `getBrandLogo()`, `getBrandCertifications()`, `getBrandReferences()`. Returns `undefined`/empty when role is absent — no fallback.
- **`app/src/components/shared/BrandLogoSection.tsx`** — both upload mutations (file + URL) pass `role: 'logo'`.
- **`app/src/components/shared/ContextPanel/index.tsx`** — all 3 LogoSelectionDialog handlers (onLogoSelected, onUploadFile, onUrlPaste) pass `role: 'logo'`.
- **`app/src/modules/Brands/BrandDialog.tsx`** — handleLogoSelected passes `role: 'logo'`.
- **`app/src/modules/Image/hooks/useImageGeneration.ts`** — logo lookup now goes through `getBrandLogo()` resolver; removed inline `find(role==='logo')`.

### Out of scope (documented for follow-up)
- 5 other call-sites still use legacy `assets[0]` (`Image/index.tsx`, `Copy/index.tsx`, `ContextPanel/index.tsx:20`, `EnhancedBrandSection.tsx:62`) — coincidentally correct because migration sets `assets[0].role='logo'`, but should be refactored to the resolver in a separate cleanup task.
- `get_brand_logo_url()` PHP helper in `base-controller.php:358` queries the unused `brand_assets` table — separate task to either fix or remove.
- `[PCM-SOND]` diagnostic logs remain in `useImageGeneration.ts` and `image/controller.php` for verification — to be removed in a separate cleanup commit once this fix is VERIFIED.
