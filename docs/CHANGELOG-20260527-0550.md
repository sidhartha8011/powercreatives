# CHANGELOG 2026-05-27 05:50 — Approvals: delete + bulk-select UX

Plugin: v1.4.11 → v1.5.0 (minor — new user-facing feature surface).

## What ships

UX pattern: Notion/Linear-style hover-actions + checkbox multi-select.
Selected via AskUserQuestion (Option A of three presented). The pattern:

- **Card hover:** a left-anchored checkbox fades in, and a red "Delete"
  chip appears in the right-side action row alongside the existing
  Copy / View-feedback chips.
- **Click checkbox:** card enters selected state (subtle blue tint +
  ring). Once any card is selected, the board enters "select-mode":
  every card's checkbox stays visible, hover-only chips are hidden,
  and the filter bar swaps for a blue "N selected | Delete | Cancel"
  bulk-action bar.
- **Click card body in select-mode:** toggles selection (Gmail/Linear
  convention — once you're selecting, the whole row is a target).
- **Delete (single or bulk):** opens a shadcn AlertDialog that blocks
  until the user confirms or cancels. Destructive action gets explicit
  consent.

The filter bar and the bulk-action bar occupy the same layout slot, so
the board below never shifts.

## Backend

### `includes/modules/approvals/service.php`

- `PCM_Approvals_Service::delete_set(int $id, int $user_id): bool`
  Single-row DELETE scoped by `userId` in the WHERE clause — a user
  cannot delete another user's set.
- `PCM_Approvals_Service::bulk_delete_sets(array $ids, int $user_id): int`
  Single SQL `DELETE … WHERE userId = %d AND id IN (…)` with `%d`
  placeholders per id. Ownership enforced server-side; ids not owned
  by the caller are silently skipped (no partial-rollback semantics
  needed). Returns the count of rows actually deleted.

### `includes/modules/approvals/controller.php`

Two new routes registered with `edit_posts` permission:

- `DELETE /approvals/sets/(?P<id>\d+)` → `delete_set` handler.
  Returns `{ id, deleted: true }` on success, 404 if not found or not
  owned, 400 if id missing, 500 on exception.
- `POST   /approvals/sets/bulk/delete` → `bulk_delete_sets` handler.
  Body: `{ ids: number[] }`. Returns `{ deleted: <count> }`. Mirrors
  the `brands.bulkDelete` precedent.

## What is NOT included (deferred, separate scope)

- **Move-to bulk action.** The bulk-action bar only has Delete + Cancel.
  Adding "Move to ▾" is the natural next iteration but was not in this
  scope to keep the diff focused. Easy to add — same selection state,
  loop calling `updateStatus` per selected id, or a new bulk-status
  endpoint server-side for atomicity.
- **Shift+click range selection.** Single-card toggle only for MVP.
  Power-user feature, separate task.
- **Long-press on touch.** Currently checkbox only appears on hover —
  on touch devices users will need to tap-hold the visible checkbox
  area. Long-press-to-enter-select-mode is a polish task.
- **Undo-toast pattern instead of confirm dialog.** Faster but more
  complex (needs to retain payload + rollback path). Modal confirm
  is the safer first cut.
- **Optimistic update via `flushSync` on delete.** Delete doesn't
  interact with the DnD library so doesn't need the synchronous-
  render guarantee. Plain optimistic write is fine.
- **Removing the duplicate `useApprovalSets()` call in `index.tsx`.**
  Still a code smell, still no UX impact. Separate task.
