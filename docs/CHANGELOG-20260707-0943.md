# Changelog — 2026-07-07 09:43 — Deliveries table: inline-editable cells + native sub-rows (+ expand-lag fix)

## Summary
Three user requirements on the new Deliveries table view:
1. Every cell is inline editable (card auto-save contract).
2. Expanded rows are native rows of the SAME grid, not an embedded table.
3. No lag on expansion (root-caused: lazy first-expand fetch + a lying empty state).

One atomic commit for the DataTable API change + its only consumer — splitting the
pair would have left an intermediate commit that doesn't build.

## Changes
- **`ui/data-table.tsx`** — `renderExpanded` (panel in one full-width cell) REPLACED by
  `renderSubRows`: the consumer returns real `<tr>` elements rendered as native
  siblings under the expanded row, inheriting the grid styling (borders, h-9 rhythm).
  `<tr data-subrow>` remains as the opt-out escape hatch. Chevron column unchanged.
- **`Deliveries/table/DeliveriesTable.tsx`** — rewritten:
  - Inline editors in every cell, all with the delivery card's contract (optimistic
    apply → single-field PATCH via `useDeliveries.updateDelivery` → silent success,
    toast + REVERT on failure): Name (`InlineTextCell`, required — empty reverts),
    Client (text, empty → null), Brand (borderless select), Type (select; applies the
    central type→modules preset exactly like the card), Status (select; trigger IS the
    lane pill). Updated stays read-only (derived). `InlineTextCell`: Enter commits,
    Esc cancels (ref-flagged so Esc's own blur can't commit a stale draft).
  - Row click REMOVED (cells own the click now); the delivery card opens via a quiet,
    always-visible Maximize2 affordance on the name cell (not group-hover — that's a
    no-op on coarse pointers, known gotcha).
  - `ProjectSubRows` — projects render as grid-native rows: chevron col empty | name
    (indented, hierarchy via indent) | site connect/disconnect select | Images | Copy |
    Videos jump buttons (self-labeled, no second header row) | hover-quiet ✕ unassign.
    Trailing sub-row = the same AddProjectMenu the card header has. Loading state is an
    explicit "Loading projects…" row.
  - **Lag fix:** `assets.getProjects` + `sites.list` are warmed at TABLE mount (the
    queries fetch all projects anyway; per-delivery filtering is client-side), so the
    sub-row hook resolves from cache — expansion is instant. Previously the queries
    mounted lazily on first expand (network wait) and the hook reported the loading
    gap as "no projects" (empty-state flicker).
- **`Deliveries/DeliveryProjects.tsx`** — `useDeliveryProjects` now exposes
  `isLoading`; consumers must show a loading state, never "no projects" while
  fetching. `DeliveryProjectsBody` (the card's feather-light table) is UNCHANGED —
  that recipe is correct inside a card; it was only wrong inside the grid.
