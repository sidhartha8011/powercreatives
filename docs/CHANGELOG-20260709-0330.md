## What ships

Every header now owns its section (heading + following paragraphs until the
next heading). Two new dynamic-rule targets, end-to-end:

- **`section` (replace):** swap a WHOLE section — merge/split/delete/add
  paragraphs, headings, lists — served render-time by the connector.
  Match = normalized heading text + level (+ occurrence hint); the guard is a
  **fingerprint** of the section's original paragraph texts: any client edit
  inside the section → rule misses → ORIGINAL serves + stale count. Never a
  wrong swap, never a silent overwrite.
- **`sectionInsert`:** a complete NEW section (FAQ etc.) anchored
  before/after an existing heading. 'after' lands before the NEXT section's
  heading (top-level, outside builder wrappers); the page's last section
  falls back to after-its-last-block.

## Hub (power-creatives)

- `PCM_Text_Matcher` gains the fixture-tested v2 reference:
  `fingerprint()`, `parse_blocks()`, `parse_replacement_units()` (lists in
  rewrites are never dropped), `apply_section_rule()` (all-or-nothing,
  wrapper-safe: same-tag block swaps keep the ORIGINAL block's attributes so
  builder styling survives; surplus new blocks ride as siblings; surplus
  originals removed whole), `apply_section_insert()`.
  +14 unit tests in tests/unit/TextMatcherTest.php.
- `PCM_SEO_Service`:
  - `save_section_rule()` — UPSERT (site+post+heading identity), CLEAN REVERT
    (replacement reproducing the original section deletes the rule), ABSORB
    (paragraph rules covered by the section are deleted in the same push —
    no mixed states), capability check BEFORE any write, push-fail ROLLS BACK
    via full-set snapshot/restore (ids preserved).
  - `save_section_insert()` — UPSERT by rule id; empty replacement on an
    existing insert = clean removal; same rollback law.
  - `remote_optimize_section()` — AI whole-section rewrite / new-section
    draft (staged, never saved) via the new **`section` prompt**
    (prompts.php, generate+optimize, block-HTML output law) — auto-seeded as
    a user-editable Template like every other section.
  - **Re-key on heading edit** (interaction law): a successful remote heading
    source-edit re-keys section rules anchored to it (matchText/occurrence/
    level) and re-pushes; push-fail restores — hub and connector always agree.
    `remote_update_heading()` gained an optional trailing `$user_id` (additive;
    routing core extracted to `remote_update_heading_apply`, behavior identical).
  - `connector_rules_schema_version()` (0/1/2 capability read);
    `push_rules()` sends **schemaVersion 2 ONLY when section targets are
    present** — paragraph-only posts keep pushing v1 byte-identical (zero
    regression on un-updated connectors), and a v2-needing push against an old
    connector fails honestly naming v2.8.0 + the Connector column.
  - `rules_to_schema()` target-aware (`section:{level, fingerprint|position}`);
    `list_dynamic_rules()` now also returns the decoded section context
    (additive — phase-2 overlay reads it).
- Routes: `POST /seo/sites/{id}/content/{post}/section-rule`
  (kind:'replace'|'insert') + `POST …/section-optimize`. tRPC:
  `seo.remoteSaveSectionRule`, `seo.remoteOptimizeSection`.

## Known limitations (documented in the contract, honest by design)

Removed `<p>`s can leave empty builder wrappers (spacing); count-changing
rewrites on multi-column builder sections re-flow into surviving blocks;
inserted sections inherit the container they land in. The authenticated
preview modal shows served truth immediately.
