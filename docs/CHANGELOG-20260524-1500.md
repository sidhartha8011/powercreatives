# Changelog — 2026-05-24 15:00

## Approvals module: shared Kanban primitive + 6-status taxonomy

Goal: refactor the internal Approvals module so the kanban + filter + sort
infrastructure is fully reusable across modules and adding a new visual
treatment, filter, sort, or column = a 1-line declaration change. No
runtime skin switcher — one beautifully-architected presentation layer.

### PR1 — Shared Kanban primitives (additive, no consumer change)
- Add `src/components/shared/Kanban/` with public surface: `KanbanBoard`,
  `KanbanToolbar`, `KanbanErrorBoundary`, default `Empty/Loading/Error`
  state UIs, filter engine (`useListState`, `applyFilters`, `applySort`),
  control registry (`SearchableSelect`, `Boolean`, `DateRange`, `Text`),
  factories (`searchableSelect`, `sortBy`, `booleanFilter`, …) — all
  domain-agnostic and strict-typed.
- Tokens via CSS custom properties on `.pck-root`; layout via CSS Modules
  (`kanban.module.css`, `filters/filters.module.css`).
- URL synchronization via `useListState({ persistKey })`, namespaced per
  board, 250 ms debounce on text inputs, `prefers-reduced-motion` honored.
- README documents the contract, the 1-line add-filter pattern, the 30-line
  add-control-kind workflow, type-safety policy, and accessibility rules.
- Add `src/components/shared/lib/brand.ts` (`getBrandInitial`).
- Add `src/vite-env.d.ts` to pull in Vite's CSS-Module type declarations
  (was missing — `*.module.css` imports were untyped before).

### PR2 — Approvals status taxonomy: 3 → 6 values
- `includes/modules/approvals/service.php`: add `STATUSES` and
  `LEGACY_STATUS_MAP` class constants. New taxonomy is
  `draft / internal / client / approved / live / archived`.
- `submit_review` now transitions to `approved` (was `completed`).
- `includes/core/db/class-pcm-schema.php`: new
  `migrate_approval_set_statuses()` remaps legacy `review → client` and
  `completed → approved`. Idempotent, defensive against missing table.
- `includes/class-pcm-activator.php`: v1.8.0 upgrade block calls the
  migration once.
- Bumps: `PCM_VERSION` 1.2.1 → 1.3.0, `PCM_DB_VERSION` 1.7.0 → 1.8.0,
  plugin header version updated to 1.3.0.

### PR3 — Extract data + dialog from the orchestrator
- New `src/modules/Approvals/types.ts` — `ApprovalStatus`, `APPROVAL_STATUSES`
  (kept in sync with PCM_Approvals_Service::STATUSES), `ApprovalSet`,
  `SnapshotAsset`, `Article`. Replaces the inline interfaces in index.tsx.
- New `src/modules/Approvals/hooks/useApprovalSets.ts` — owns the tRPC
  query (cache key preserved verbatim), derives counts by status, exposes
  typed `getPublicBoardUrl`, `copyShareLink`, `feedbackSet`,
  `openFeedback`, `closeFeedback`. No JSX, no globals; window access is
  isolated to a single helper.
- New `src/modules/Approvals/kanban/FeedbackDialog.tsx` — extracts the
  120-line inline dialog into a pure presentational component. Empty
  sections are hidden instead of rendering empty headers.

### PR4 — Sets kanban consumer
- New `src/modules/Approvals/kanban/`:
  - `setColumns.ts` — 6 Notion-style pastel columns.
  - `setFilters.ts` — three searchable selects (brand, set name, project),
    each declared in a single line.
  - `setSorts.ts` — newest / oldest / recently updated.
  - `SetCard.tsx` + `setCard.module.css` — Notion-minimal card body
    (brand · name, project · counts · feedback) with hover-revealed
    action row (copy link, preview, view feedback).
  - `SetsBoard.tsx` — thin orchestrator binding hook + declarations +
    shared `KanbanToolbar` + `KanbanBoard`.
- `src/modules/Approvals/index.tsx` — Sets tab content (was lines 305-447
  of inline JSX) replaced by `<SetsBoard />`. Feedback dialog state and
  copy-link logic removed (now in the hook).

### PR5 — Articles kanban consumer (proves reuse)
- New `src/modules/Approvals/hooks/useApprovalArticles.ts` — same
  pattern as `useApprovalSets`: tRPC list query + counts + typed
  `changeStatus` mutation handler.
- New `src/modules/Approvals/kanban/`:
  - `articleColumns.ts` — 4 columns (`draft / review / ready / published`)
    using accent colors from existing `statusColors` tokens.
  - `articleFilters.ts` — title text filter + "Live only" boolean toggle.
  - `articleSorts.ts` — updated / newest / oldest / title A→Z.
  - `ArticleCard.tsx` + `articleCard.module.css` — title + metadata +
    status select. Status select remains pending DnD (out of scope).
  - `ArticlesBoard.tsx` — second consumer of the shared kanban, proving
    the primitive is genuinely reusable across domains.
- `src/modules/Approvals/index.tsx` — final form: ~80 lines (down from
  576). The legacy `ArticleKanbanColumn` component removed entirely. The
  orchestrator owns only the page chrome and tab labels.

### Final verification
- `npm run check`: 65 errors, identical to pre-refactor baseline. Zero
  errors introduced by the new code.
- `npm run build`: clean — 2073 modules transformed, dist bundles
  produced (index.css 230 kB / index-writer.js 4.07 MB / 794 kB gzipped).
- Net code delta: the inline JSX block in `index.tsx` (~440 lines) is
  replaced by 14 small, single-purpose files. Adding a new sort/filter/
  column is a one-line declaration change. Adding a new control kind is
  ≈30 lines and the compiler walks you through every step.

### Out of scope (documented, not introduced as new debt)
- Client-facing review board (`components/ClientReviewPage.tsx`,
  `ClientBreadcrumbs.tsx`, `ClientStatusToolbar.tsx`, `CreativeAssetCard.tsx`)
  — has 376 lines of inline `<style>` and its own pcm-* class system.
  Separate refactor scope; not touched here.
- Drag-and-drop. The Card slot contract reserves `dragHandleProps` /
  `isDragging` props so DnD can be added without churning every card
  consumer.
- Test infrastructure. Engine functions are written as pure functions so
  they're trivial to unit-test once Vitest/RTL is added.
