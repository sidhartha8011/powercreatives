# CHANGELOG — 2026-08-06 05:24 — APPROVAL DOCUMENT PERSISTENCE AND BACKDROP REPAIR

- GATE 1 DIALOG BOUNDARY: preserved the visible 95vw × 90vh client-preview panel while separating it from a transparent viewport-sized Radix host. The approval document now uses a controlled nested Radix dialog instead of a manual body event listener and `createPortal`; its existing 12px blur overlay can cover the viewport, and backdrop, Escape, focus trapping and body-scroll ownership come from one modal primitive. No typography, document dimensions, card layout, workflow or API changed.
- GATE 1 OUTSIDE DISMISSAL: bound document dismissal to the transparent fullscreen interaction host that receives clicks above the visual backdrop, while the document modal stops its own click events from reaching that host.
- GATE 2 SERIAL AUTOSAVE: changed the shared debounced saver to a single-writer drain. A newer draft waits behind the active request, query refetches cannot replace dirty local work, failed background saves retry on the existing two-second cadence, and explicit flushes reject instead of reporting success.
- GATE 2 CLOSE GUARANTEE: routed backdrop, Escape and X through one idempotent close promise. Editing locks after close intent, the latest draft is flushed, confirmed success closes the document, and a failed write leaves it open for retry.
- GATE 3 EDITOR CLOSE BARRIER: registered one editor-owned preparation promise with the document. Paste/drop image uploads, annotations and drawing uploads are tracked; an active drawing is committed, pending media work settles, its resulting document change enters autosave, and only then may the document flush and close.
- VALIDATION HYDRATION FIX: stopped Tiptap's initial `setContent` hydration and extension-normalization transactions from entering autosave. The editor accepts updates after its first interactive frame, so opening an unchanged approval document no longer produces a ghost write while actual user edits are unchanged.
- VALIDATION RECORDS: added the functional, architecture and UX checklists plus the separate improvements/regression table with build, static, browser, persistence and database-restore evidence.
