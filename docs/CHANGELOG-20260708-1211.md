## The engine (connector 2.6.3 → 2.7.0 — ONE bump, bundles everything)

- **Render-time rule serving:** `template_redirect` + `ob_start` (prio 2),
  front-end singular only; ENTIRE callback in try/catch → any throwable
  serves the ORIGINAL buffer (a rule can never break a client page). Site
  kill-switch option (`pcm_conn_rules_off`) honored from day one.
- **Matching:** boundary match on non-nestable tags + normalization spec v1
  (entity-decode → NBSP → whitespace-collapse → trim → case-fold),
  occurrence-aware. Miss → block untouched + throttled per-post miss counter
  (max one DB write / 5 min). v1 serves `target:'paragraph'`; engine is
  target-agnostic (heading/anchorText/href reserved, never guessed at).
- **Storage:** `pcm_conn_rules_{postId}` options (autoload OFF — render loads
  only the current post's rules) + `pcm_conn_rules_index`. NOT the 200-cap
  overrides list (that stays heading-override-only).
- **Rules API:** `GET /pcm-conn/v1/rules` (capability answer + a post's rules
  & counters) · `POST` replaces a post's set — validates `schemaVersion===1`
  (rejects others honestly), sanitizes (target whitelist, re-normalize match
  text, `wp_kses_post` replacement), purges caches.
- **`GET /pcm-conn/v1/scan-content`:** the paragraph inventory in TRUE
  rendered document order (hardened loopback; `<body>` minus
  header/nav/footer/aside chrome), each node `{text, html, occurrence,
  anchor}`. `pcm_cscan` requests are EXCLUDED from rule serving so the
  inventory is always the ORIGINAL text rules match against. Loopback blocked
  → honest `{nodes:[], error:'loopback_blocked'}`.
