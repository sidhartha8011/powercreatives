# Image annotation save latency repair — 2026-08-06 06:44

## Scope

- Preserve the default WordPress Media Library upload behavior for every existing storage consumer.
- Let Writer/Approvals inline editor images opt out of synchronous thumbnail generation because those editors store and render the original attachment URL only.
- Keep the document open when an annotation or drawing upload fails during close preparation.
- Reuse the existing save-state label to show that close preparation is still saving; no layout or visual design was changed.

## Root cause

The annotation attachment and document snapshot were both persisted, but full WordPress image processing held the upload REST request open before the approval snapshot could receive its URL. The existing attachment timestamp preceded its snapshot update by 35 seconds. On the real application route, the original-only metadata path completed every server stage in 0.135 seconds for the same annotation flow.

## Risk controls

- Thumbnail suppression is an explicit final argument used only by the `writer-inline-image` call site.
- `PCM_Storage::upload()` and `PCM_Storage::save_data()` retain full metadata generation by default.
- The inline fast path records WordPress-compatible original dimensions, relative file path and file size, while the default path still runs full WordPress metadata generation.
- Failed media work rejects the current close request, but is removed from the pending set so the user can retry or deliberately close afterward.
