# Changelog — 2026-06-01 03:00 — Copy Framework

Feature: template-driven, dropdown-selected copywriting framework injected via its own
`{{copyFramework}}` placeholder (keeps the Creative Brief clean). Mirrors the proven
`creativeBrief` wiring; reuses the declarative placeholder registry.

- `app/shared/templateTypes.ts` — added `framework` to `TEMPLATE_CATEGORIES`, `CATEGORY_LABELS`, `CATEGORY_DESCRIPTIONS`.
- `app/src/modules/Templates/TemplateDialog.tsx` — added `framework` badge color + label/value placeholder cases (auto-surfaces in the category dropdowns there and in TemplateRow).
- `app/src/modules/Copy/frameworks.ts` — NEW. `BUILT_IN_FRAMEWORKS` library (Hook-Story-Offer, Epiphany Bridge, Emotion-Speed-Fire, AIDA, PAS), distilled from docs/modules/copy/.
- `app/src/modules/Copy/templatePopulator.ts` — `buildTemplatePopulation` collects `framework` entries → `frameworks[]`, default-selects the first (`copyFrameworkName` + `copyFramework`); `buildTemplateClearUpdates` gained `frameworkWasModified` (conditional clear).
- `app/src/modules/Copy/index.tsx` — `frameworkOptions` state (built-ins ∪ template), `lastAppliedFrameworkRef`; framework `<select>` rendered after the Creative Brief; apply/clear branches set options + conditional-clear baseline.
- `includes/modules/copy/service.php` — `build_copy_system_prompt()` `$vars` now includes `copyFramework`; `{{copyFramework}}` slot added to default `system_prompt_ads` + `system_prompt_organic` (between CREATIVE BRIEF and OUTPUT FORMAT). Not added to angle/audience prompts.
- `includes/core/class-pcm-prompt-placeholders.php` — added `copyFramework_system` INJECTIONS entry (modules copy+ads, sections ads+organic, anchor `OUTPUT FORMAT:`).
- `power-creatives.php` — `PCM_DB_VERSION` 1.12.0 → 1.13.0.
- `includes/class-pcm-activator.php` — `maybe_upgrade()` v1.13.0 step runs `PCM_Prompt_Placeholders::sync_all()` (idempotent) to patch existing copy/ads prompts.
- `app/src/modules/Settings/PromptEditorSection.tsx` — documented `{{copyFramework}}` in the copy + ads placeholder reference.

Behavior: no framework selected → `{{copyFramework}}` vanishes (prompt identical to before). Ads
consumes it automatically via the shared `/copy/generate` + `['copy','ads']` injection.

## Revision (same session) — source frameworks from templates, not hardcode

Per user direction: the Framework dropdown must list real framework templates, not a hardcoded set.
The per-entry classifier is the **Subtype** column (code: `category`).

- DELETED `app/src/modules/Copy/frameworks.ts` (hardcoded `BUILT_IN_FRAMEWORKS` removed).
- `app/src/modules/Copy/index.tsx` — Framework dropdown now sources from `trpc.templates.list({module:'copy'})`,
  listing templates whose entry `category === 'framework'` (`{ name: template.name, text: entry.value }`),
  via a `useMemo`. Local `FrameworkOption` type. Empty-state hint added. Standalone selection —
  decoupled from template apply/clear (removed `lastAppliedFrameworkRef` + the apply/clear framework code).
- `app/src/modules/Copy/templatePopulator.ts` — reverted framework handling; `framework` entries are no
  longer consumed during template-apply (the dropdown owns frameworks). `buildTemplateClearUpdates`
  signature back to `(currentValues, briefWasModified, tonalityWasModified)`.

Backend (service.php vars + `{{copyFramework}}` slot), the `copyFramework_system` injection, and the
1.13.0 migration are unchanged — still correct. To populate the dropdown, set existing copy templates'
**Subtype → Framework** (e.g. Hook-Story-Offer, Epiphany Bridge, Emotion Speed Fire, currently Subtype=Brief).

## Seed fix — reclassify the 3 framework templates

`includes/core/class-pcm-template-seeds.php` — changed entry `category` from `'brief'` to `'framework'`
for the three seeded copy templates (Epiphany Bridge (Full), Hook-Story-Offer, Emotion Speed Fire);
`type` was already `social_ads` and `niche` already `General`. Comments updated (no longer "populates
creativeBrief"). Fresh installs now seed these as frameworks → they appear in the Copy Framework dropdown.

NOTE: seeds are insert-if-missing, so this does NOT update already-seeded DB rows. To apply to an existing
install: delete the 3 templates in the Templates UI, then re-seed (deactivate/reactivate the plugin) — or
flip their Subtype to Framework inline in the table.
