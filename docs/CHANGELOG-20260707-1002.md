# Changelog — 2026-07-07 10:02 — Header bands, popover border-over-shadow, Type pill

## Summary
Design pass on the Deliveries table per user feedback: dropdown popovers get edge
definition from a border instead of a heavy shadow (GLOBAL — popover chrome must be
identical app-wide), the main header becomes a light-gray band, expanded projects get
their own whisper-gray sub-header row, and Type values render as neutral pills.

## Changes
- **GLOBAL popover chrome** (`ui/select.tsx` SelectContent, `ui/dropdown-menu.tsx`
  Content + SubContent): `shadow-md`/`shadow-lg` → `shadow-sm`, border strengthened
  to `border-slate-300`. Border does the edge, shadow is a whisper. Affects every
  select/dropdown in the app — flagged to the user as the recommended scope and
  approved ("implement properly").
- **Deliveries main header band** — `[&>thead>tr>th]:bg-slate-50` via the DataTable
  `className` prop (tailwind-merge overrides the grid's `bg-card` for the same
  variant+group). Sticky behavior unchanged. Deliveries-scoped.
- **Projects sub-header row** — expanded rows now start with an `aria-hidden` label
  row: Project | Site | Images | Copy | Videos on `bg-slate-50/60` with 10px muted
  ink. Hierarchy reads: slate-50 = table header, slate-50/60 + smaller ink = section
  header, white = data. Labels match each column's content indent (pl-4/pl-1/pl-2)
  so header and value ink align optically. aria-hidden because the controls beneath
  carry their own aria-labels — the row is visual duplication.
- **TypePill** — Type cell + closed select trigger render a neutral tag pill
  (bg-slate-100 / text-slate-700, same anatomy as StatusPill). One quiet color for
  all types: types are admin-defined presets with NO color in the data — inventing
  per-type colors would be a guess. Per-type colors = a `color` field on the Delivery
  Types preset schema (separate approval, noted in the session log).
