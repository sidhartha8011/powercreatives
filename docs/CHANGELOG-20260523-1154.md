# Changelog — 2026-05-23 11:54

## Role-Based Logo Resolution (Architecture Refactor)

**Problem:** Two competing contracts for "what is the brand logo":
- Position-based: `assets[0]` (BrandDialog, BrandLogoSection, useBrandAssets, Image module)
- Role-based: `role === 'logo'` (brandAssetResolver, resolveGenerationPayload, ContextPanel)

This caused logos showing wrong images, reference images appearing as logos, and fragile reorder-to-position-0 hacks throughout the codebase.

**Solution:** Eliminated the position-based contract entirely. `role === 'logo'` is the single source of truth.

### Changes

#### Frontend
- `BrandDialog.tsx`: `logoAsset = getBrandLogo(liveBrand)` instead of `liveAssets[0]`
- `BrandDialog.tsx`: Removed all reorder-to-position-0 logic from `handleLogoSelected`
- `BrandDialog.tsx`: `handleSetAsLogo` now uses `POST /brands/{id}/assets/set-logo` (role-swap)
- `BrandLogoSection.tsx`: Removed reorder hacks from upload + URL fetch handlers
- `ReferenceImageSelector.tsx`: Filters out `role === 'logo'` assets (logos shown in BrandLogoSection only)
- `useBrandAssets.ts`: `removeLogo` uses `getBrandLogo()` instead of `assets[0]`
- `Image/index.tsx`: Removed `assets[0]` fallback when no logo found

#### Backend
- New endpoint: `POST /brands/{id}/assets/set-logo` — atomic role-swap
- New service method: `set_asset_as_logo()` — promotes target to 'logo', demotes old logo to 'reference'
