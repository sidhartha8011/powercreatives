# Changelog — 2026-07-07 06:00 — Card tokens: root typography, spacing, WP-bleed fix

## Summary
The EntityCard primitive now owns ALL typography and spacing via tokens; card components
were swept of every raw text/spacing class. Four type roles, two inks, two weights — the
"looks like 4 different fonts" report is fixed at the root, and WordPress-admin CSS can no
longer style anything inside a card.

## New — components/shared/EntityCard/cardTokens.ts
- CARD_TYPE: TITLE (32px/700, literal !-marks to beat the Input variant's md:text-sm),
  BODY (13px/400/foreground — all values/controls/notes), LABEL (12px/400/muted — headers,
  meta, counts, timestamps, chips, placeholder ink), SECTION (11px/600/uppercase/muted).
  Every role sets size+ink+weight+line-height explicitly → the Radix portal into wp-admin
  leaves WP's global input/select CSS nothing to fill (root bleed fix, no !important war).
- CARD_SPACE: COLUMN (760px, pt-10 — tightened to the Notion reference), TITLE_GAP,
  SECTION_GAP, SECTION_HEADER_GAP.
- In-file contract: components inside a card may not carry raw text-*/font-*/padding
  classes — roles and tokens only.

## Sweep
- tableRecipe: header cells = LABEL, body cells = BODY.
- EntityCard / EntityCardTitle / EntityCardSection / PropertyTable / DeliveryDialog
  sections: all text nodes now reference roles. Specifically killed: 10px chips,
  font-medium project names, 12px selects inside 13px cells, 14px log notes, 11px
  timestamps. Placeholders: body size, label ink (absence changes ink, never size).
- Floating dropdown menus keep the app-wide menu styling (not card surface).
