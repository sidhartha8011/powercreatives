## 3. NEW FUNCTIONS/PIECES CREATED TODAY — purpose reference

**Hub `PCM_Text_Matcher` (includes/modules/seo/class-pcm-text-matcher.php):**
- `fingerprint(texts)` — section identity: normalized ¶ texts joined by \n;
  THE guard that makes serving refuse anything the user didn't approve.
- `parse_blocks(html)` — top-level h1–6/p blocks with byte offsets.
- `parse_replacement_units(html)` — a rewrite's blocks + raw chunks (lists
  survive).
- `chrome_spans(html)` / `content_blocks(html)` — exclude pre-<body> +
  header/nav/footer/aside so serving compares the same block set the scan
  fingerprinted (2.8.1 parity).
- `apply_section_rule(...)` — all-or-nothing wrapper-safe section swap:
  verify fingerprint first; same-tag blocks keep ORIGINAL attrs (builder
  styling survives); surplus new blocks ride as siblings; surplus originals
  removed whole; miss → null (original serves).
- `apply_section_insert(...)` — new section before anchor heading / after
  section end (top-level when a next heading exists).
- Connector carries `pcm_conn_*` mirrors of the above (THE D1 DEBT — dies in
  cleanup C3; until then the sync contract + parity harness guards it).

**Hub `PCM_SEO_Service` (includes/modules/seo/service.php):**
- `save_section_rule()` — UPSERT by heading identity; CLEAN REVERT (editing
  back to original deletes the rule); ABSORBS covered paragraph rules;
  capability-checked; push-fail rolls back via snapshot (ids preserved).
- `save_section_insert()` — UPSERT by rule id; empty replacement = removal.
- `remote_optimize_section()` — staged AI rewrite/draft (never saved); topic
  = free instruction; `run_prompt_section` appends the instruction honestly
  when a seeded/user template predates `{{topic}}`.
- `record_section_version()` / `list_section_versions()` /
  `delete_section_version()` — version history (see table purpose above).
- `publish_post_rules()` + `write_draft()` — REMOVED (drafts paused);
  `post_rule_rows()`/`restore_rule_rows()`/`push_current_rules_or_rollback()`
  — snapshot/rollback used by all save paths.
- `connector_rules_schema_version()` — capability read (0/1/2); push sends v2
  only when section targets exist (old connectors keep v1 byte-identical).
- `remote_update_heading()` wrapper + `remote_update_heading_apply()` — the
  edit core reports its layer via `$via` ('source'/'override'); ANY successful
  heading edit re-keys section rules (`rekey_section_rules()`); push-fail
  restores.
