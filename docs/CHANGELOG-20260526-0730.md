# CHANGELOG 2026-05-26 07:30 — Kanban Visual Refactor: Round 3 Fixes

Round 3 from user feedback: borders STILL missing on filter dropdowns
despite the round-2 attempt. Senior-dev investigation revealed the
actual cause + a clean fix.

Plugin: v1.4.2 → v1.4.3

## Root cause (the real one this time)

The three filter dropdowns (Brand / Project / Approval set) are rendered
by `SearchableSelect.tsx`, which wraps shadcn's `<Button variant="ghost"
size="sm">`. The `ghost` variant's `cva`-generated Tailwind utilities
include:

- `hover:bg-accent` (no background at rest)
- `h-8`, `px-3`, `rounded-md`, `text-sm`, `transition-all` (size="sm")
- explicitly **no border, no shadow, no background**

My `.trigger` CSS Module class was being merged via `cn()` but lost the
specificity / source-order war against Tailwind's utility classes for
properties Tailwind set (height, padding, radius, font-size, transition).
For properties Tailwind didn't set (background, border, shadow), my CSS
should have applied — but in production it didn't, likely because the
ghost variant's "no background" gets translated by tailwind-merge into
explicit utility classes that win source order.

Either way: fighting shadcn's Button via CSS Module is fragile. The
senior-dev fix is to stop fighting it.

## Fix

### Replace shadcn `<Button>` with a raw `<button>` element

`SearchableSelect.tsx`: dropped the `Button` import and its `variant`
/`size` props. The trigger is now a plain `<button type="button">` so
`filters.module.css` `.trigger` owns 100% of the visual.

This is a **markup-only** edit (no logic, no behavior change). Radix's
`<PopoverTrigger asChild>` Slot pattern accepts any element — the
ref-forwarding and prop-spreading work identically with a raw button.

### `.trigger` upgraded to a self-contained input style

Now that the shadcn Button reset is gone, `.trigger` has to provide every
property a button needs (no more inheriting from Button's `cva` base):
- `display: inline-flex; align-items: center; justify-content: space-between`
- `font-family: inherit; line-height: 1`
- `cursor: pointer; outline: none; white-space: nowrap`
- `:focus-visible` ring (blue, matches the active state)
- `.triggerChevron` class for the ChevronsUpDown icon (was inline
  Tailwind classes `h-3 w-3 opacity-60 shrink-0`)

### Lane bg pushed clearly cool

`--pck-bg-lane`: `#f4f4f5` → `#eef0f4`. RGB(238, 240, 244) has 6 units
more blue than red — visibly cool, light enough to read as "light grey",
no warm bias. The previous values (#f5f5f4 stone, #f4f4f5 zinc) were
nominally neutral but read warm against the white page.

`--pck-bg-toolbar`: `#fbfbfc` → `#fafbfc` — keeps it just barely
distinct from the page, harmonized with the cooler lane bg.
