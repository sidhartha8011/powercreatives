# Changelog — 2026-07-07 13:30 — Create-from-delivery: "+" icons → pre-mapped creation

## Summary
From an expanded delivery, every project row can now spawn content with zero
manual mapping: "+" on the Images/Copy/Videos/Approvals cells opens the matching
module with brand, delivery, and project pre-selected — whatever gets produced is
born correctly attached. Plus a new Approvals count per project row.
(The SEO SERP-check action was DROPPED from this batch per user — no SEO table
changes for now.)

## Pair 1 — [create-from-delivery-seam] (3e2d0c7 → 758c74a)
- **AppContext `PendingCreateContext`** — `{ module: image|copy|video|approvals,
  brandId, deliveryId, projectId }` + `navigateToCreate(ctx)` /
  `consumePendingCreate(module)`. Same one-shot pattern as pendingProjectNav;
  the consume is module-checked so a context addressed to one module can never
  leak into another.
- **Delivery project sub-rows** — every count cell gains a quiet "+"
  (`createPlus`) that fires navigateToCreate with the full chain (project = the
  row, delivery = the parent, brand = the delivery's brand).
- **NEW Approvals cell** (replaces a spacer; sub-header labeled): count of
  approval sets per project via a FRONTEND join on `approvals.listSets`
  projectId — the assets module never reads approvals tables server-side.
  Count is informational (no approvals tab in the project detail to jump to);
  the "+" creates. Sets query warmed at table mount like projects/sites.

## Pair 2 — [create-from-delivery-consumers] (4276d1c → ae2852e)
- **Image / Copy / Video** — on mount each consumes its pending context:
  fetches the brand (`utils.client.brands.getById`, Copy's own refresh pattern)
  and sets ContextPanel state; the target project rides on `brand.projectId`,
  the prop path Image's save flow already reads. Fetch failure toasts — the
  user lands unpreselected, never silently mis-mapped.
- **Approvals** — consumes by opening the "Add Approval Set" flow with the
  preset: `CreateCustomSetDialog` gained an optional `preset` prop forwarded to
  `SendToApprovalSetDialog` (existing `brandId`/`projectId` props + NEW
  `defaultDeliveryId`, which wins over the brand-matched delivery guess; user
  can still change everything).
