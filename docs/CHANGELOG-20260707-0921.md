# Changelog — 2026-07-07 09:21 — Deliveries: table view + Kanban ⇄ Table toggle

## Summary
Deliveries is now viewable as a sortable table alongside the existing Kanban — a
segmented toggle in the filter bar switches views (persisted per browser). Table rows
expand like an accordion to show the delivery's projects — the exact same list the
delivery card shows, extracted to one shared source.

## Changes
- **NEW `Deliveries/DeliveryProjects.tsx`** — ProjectsSection's data hook + add-menu +
  table extracted from DeliveryDialog (moved verbatim: site connect/disconnect select,
  Images/Copy/Videos jump cells, disabled Articles, hover-✕ unassign, dashed add empty
  state). Exports `useDeliveryProjects`, `AddProjectMenu`, `DeliveryProjectsBody`.
  DeliveryDialog's ProjectsSection is now thin glue (EntityCardSection + header action
  + body) — card behavior unchanged.
- **NEW `Deliveries/table/DeliveriesTable.tsx`** — built on the global DataTable
  (same minimalist grid as Sites/SEO). Columns: Delivery | Client | Brand | Type |
  Status | Updated, all header-click sortable (Status sorts in pipeline/lane order;
  pill colors reuse `deliveryColumns` lane accents). Row click opens the delivery
  card, exactly like clicking a Kanban card. Chevron expands to the projects list.
  Default sort Updated desc (mirrors the board's 'Recently updated').
- **`DeliveriesBoard.tsx`** — Kanban ⇄ Table segmented toggle (SquareKanban/Table2,
  same chrome as Projects' grid/list switch), persisted to localStorage
  `pcm:deliveries:view` (default: kanban). Both views render from the same
  `listState.filteredItems`, so search + client filter + "Showing N" apply
  identically. The sort dropdown renders in Kanban view only — in table view the
  column headers own sorting (no competing sort systems).

## Not built (unchanged scope)

  the research pass, not approved yet. The primitive already supports it via
  `columns` + `getColumnId` when wanted.
