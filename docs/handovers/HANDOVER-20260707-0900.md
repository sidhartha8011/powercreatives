   no AI/workflow logic inside them; consumers own the smart behavior.

## 3. The domain model (5-minute version)

```
Brand ─┬─ Delivery ─┬─ Project ─┬─ assets (images/video)      [assets module owns projects]
       │            │           ├─ copy results
       │            │           └─ siteId ──► Site (wp_pcm_sites = WP connection credentials)
       │            └─ delivery_logs (work log, v1.35.0)
       └─ (approval sets, notifications reference brandId/projectId/deliveryId)
```

- Chain resolution is LIVE and central: `PCM_Hierarchy::for_project()`, 
  `site_for_project()`, `projects_for_site()` (N projects may share one site). Never 
  store derived brand/delivery ids; never query another module's FK columns directly.
- **Two different "site" concepts:** `wp_pcm_sites` (publishing/connection credentials, 
  the Sites module) vs SEO Hub tenant sites. `deliveries.seoSiteId` is DEPRECATED 
  (write-only, retired today) — do not wire it up again.
- Articles link to **sites**, not projects (this is why the delivery card's Articles 
  column is deliberately disabled).

## 5. ⚠️ The typography system — read before touching ANY styling

Today's hardest lessons. Three load-bearing mechanisms:

1. **`@import "tailwindcss" important;`** (`app/src/index.css:1` region) — REQUIRED. 
   The SPA renders inside wp-admin whose UNLAYERED core CSS (e.g. forms.css 
   `input{font-size:14px}`) beats any layered Tailwind utility. The flag emits every 
   utility `!important`. Trade-off: utilities also beat runtime inline styles — keep 
   utility classes off properties JS libs set inline (dnd transforms). Do not remove.
2. **`cn()` is an EXTENDED tailwind-merge** (`app/src/lib/utils.ts`) — custom `text-*` 
   utilities are unknown to tailwind-merge and get classified as colors → silently 
   DELETED when a real color follows. Every new `--text-*` @theme token MUST be 
   registered in the font-size group there, or `cn()` eats it.
3. **Card type tokens** — px values live in ONE place: `--text-card-*` in index.css 
   `@theme` (title 32 / body 11 / label 10 / section 11). Components consume roles from 
   `components/shared/EntityCard/cardTokens.ts` (`CARD_TYPE.BODY/LABEL/CHIP/...`). 
   CHIP derives from BODY (+ `leading-none`) and must never own a size. Contract: no 
   raw text/font/padding classes inside card components — roles/tokens only.

Known debt: `docs/backlog.md` → "Typography spaghetti cleanup" (8 systems, ~1,265 
declarations; staged plan; the 1,096 inline classes are opportunistic-only — never sweep).
